Workflows as files

Your process, in files you can read.

A workflow is a short shape file plus one Markdown file per step. Front matter says who performs the step, how strict it is, what it may read and write, and which tools it may call. The prose is the instructions.

Build it by talking
Describe the process in chat. Changes land as a highlighted draft you keep or discard.
Review it like code
Diff it, version it in git, roll it out with change control.
Checked before it runs
Every state reachable, every wait has a timeout, every outcome goes somewhere.
workflows/client-intake/workflow.yamlshape
workflow: client-intake
case: client
start: intake_form
states:
  intake_form:  { performer: client,  on: { submitted: extract } }
  extract:      { performer: agent,   on: { done: check } }
  check:        { performer: agent,   on: { clear: approve, flagged: approve } }
  approve:
    performer: role:account-manager
    timeout: 3d
    on: { approved: welcome, sent_back: intake_form }
  welcome:      { performer: system }
workflows/client-intake/steps/check.mdstep
---
performer: agent
strictness: guided
reads: [client, documents]
writes: [client.risk_flags]
tools:
  allowed:  [registry.lookup, sanctions.search]
  required: [sanctions.search]
outcomes: [clear, flagged]
---

Governance built in

Agents can reach any tool. Policy decides which calls go through.

Rules are compiled into the tool gateway and the database itself, so they hold even when the agent is wrong, confused, or reading something it shouldn't trust.

Every tool declares its effect

One line beside the schema. Tools with no declared effect count as irreversible until you classify them.

read Look something up crm.get_contact
draft Prepare without sending email.draft
write Change your own records crm.update_contact
outbound Reach someone outside email.send
irreversible Can't be undone billing.charge

Policy layers that only tighten

Each layer can add limits, never remove them. The step sees the sum, with the origin of every rule.

Plugin outbound → needs approval
Domain no outbound outside business hours
Workflow irreversible → never
Step read only, plus client.risk_flags
Agents run with a short-lived step token, so Postgres row-level security applies to them just as it does to people.

People in the loop

People are steps, not interruptions.

A person's approval is part of the workflow, with a role, a timeout and outcomes, just like an agent's step. The run waits durably, and picks up the moment they decide.

Clients and partners take part through a link, without an account.
